## 2. 共通点
- 入口はトップではなく「出演者名＋おすすめ／ランキング／ベスト○／○選」の個別ページ。1ページ1出演者。
- 本文の型は「紹介→おすすめ作品○件→関連→まとめ」。プロフィールの表と目次を持つサイトが上位。
- 収益は DMM／FANZA の公式リンク。公式埋め込みのサンプル動画を作品ごとに置くサイトが2つ。
- 名前にカテゴリ語（エロ、AV、actress）か嗜好を示す語を含むものが多い。ただし含まなくても上位の例がある（opasyuki）。

## 3. 競合の弱み（私たちの差別化点）
- 画像を自サイトに保存しているサイトが多い（規約上のリスク）。私たちは公式直リンクのみ。
- PR表記と年齢確認が不揃い。私たちは全ページに置く。
- 運営者情報・掲載停止窓口が薄い。私たちは雛形で網羅。
- 記事は人手の文章量に依存し、更新が止まりやすい。私たちはデータ駆動で全出演者分を毎日更新できる。

## 4. 私たちのサイトへの反映（決定）
1. **出演者ページを検索の入口に作り替える**。title は「{出演者}のおすすめ作品ランキング{年}｜{サイト名}」。構成は、プロフィール表（API の出演者情報。顔写真は使わない）、おすすめ作品10（ベイズ平均の上位。選定理由をラベルと数値で示す）、新着、セール中、シリーズ別、共演の多い出演者、まとめ（自動文）、目次。各作品に公式埋め込み動画（クリックで読み込み）。
2. **出演者ランキングページ**（`/ranking/actress/`）を作る。作品数・平均評価・レビュー総数から機械的に順位付けし、運営者の導入文を差し込める枠を置く。汎用語「AV女優 おすすめ」の受け皿で、ハブ記事（運営者執筆）と組にする。
3. **出演者情報の取り込み**（ActressSearch API）をデータ層に追加する。顔写真URLは保存しない。
4. シリーズ・メーカーページも同じ型に寄せる（優先度は出演者の後）。
5. 名前は「ブランド語＋カテゴリ語」の方針を維持（docs/08 7章）。
