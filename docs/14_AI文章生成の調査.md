# 14 AI 文章生成の調査（運営者からの文・作品ごとの紹介文を AI に書かせる）

2026-11-15。運営者の依頼「運営者からと各作品のコメントを AI に考えさせたい。露骨な表現を含めてできるツールを調べてほしい」への回答。Web の二次情報が中心で、各社の規約本文は原文で再確認が必要（本文中に「要確認」と記す）。

## 1. 結論

- 露骨さの段階で道具が分かれる。**非露骨（紹介・解説）は今の仕組みと Claude で今日から自動化できる。官能的（R15 相当）は Meta の Muse などの一般向けアプリで書けるが、API での自動化は規約の確認待ち。露骨（R18）で実在の出演者名を含む文は、主要な API 提供者の規約（実在人物の性的描写の禁止）に触れるため、自前でモデルを動かす以外に安全な道がない。**
- おすすめの進め方: (1) 非露骨の自動文を先に強化して公開する。(2) 自前モデル（公開重みの日本語対応モデル）で 100 作品だけ試し、品質とリスクを見てから本採用を決める。(3) 官能的な文は運営者が Muse 等で下書きして貼る運用を特集に限って使う。

## 2. 前提と制約

- リポジトリには性的に露骨な文章を入れない（CLAUDE.md）。生成文はリポジトリの外（サーバー上の非公開ディレクトリ、または非公開のストレージ）に置き、ビルド時に取り込む。
- DMM の規約: 公式の商品紹介文・レビューの転載は不可。AI が作品データ（題名・出演者・ジャンル・シリーズ・収録時間・評価）だけから書いた文は自作コンテンツとして扱える。ただし、データに無い事実（場面・行為・台詞）を書くと誤認表示や名誉の問題になるので、文は「データに基づく位置づけ」に留めるか、創作であることを明示する必要がある。
- 実在の出演者名を伴う性的な描写は、名誉・肖像の問題と、各 AI 提供者の「実在人物の性的コンテンツ禁止」条項の両方に関わる。これが今回の最大の制約。
- 18 歳未満を連想させる内容は、どの道具でも生成しない（規約以前に法律）。

## 4. 3 段階の提案

### 段階 1: 非露骨の自動文を強化（今すぐ・Claude で可能）
- 作品ごとの「位置づけ」文（シリーズ何作目、出演者の何本目、評価の分位、同メーカーでの特徴）を、今のテンプレートより自然な文にする。露骨な語は入れない。
- 運営者からの文: 週 1 回、その週の新着・セール・人気の動きをデータから要約した下書きを Claude が作り、運営者が一言足して公開する。
- 特集の下書き: テーマと作品の候補一覧を Claude が作り、選ぶ理由の文は運営者が書く（または Claude が非露骨の範囲で下書き）。

### 段階 2: 官能的な文（R15 相当）を運営者の手作業で
- Meta Muse（または AIのべりすと）で特集の導入文を下書きし、運営者が確認して貼る。作品ごとの自動化はしない。
- 実在の出演者を性的に描写しない。「作風」「見どころ」の言い回しに留める。

### 段階 3: 露骨な文（R18）は自前モデルで試験
- 公開重みの日本語対応モデルを時間貸し GPU で動かし、100 作品で試す。入力は作品データだけ。出力は非公開ストレージに保存し、リポジトリに入れない。
- 判断材料: 文の品質（不自然さ、事実の捏造の有無）、1 作品あたりの費用、生成にかかる時間、名誉・肖像のリスク（出演者名を含む性的描写をどこまで許すかの線引き）。
- 本採用するなら、ページに「この紹介文は AI が作品データから作成しました」と明示し、掲載停止の窓口で文単位の削除に応じる。

## 5. 仕組みの案（どの段階でも共通）
- 生成文の置き場: mixhost のサーバー上、公開ディレクトリの外（例: `/home/<ユーザー名>/data/copy.sqlite`）。GitHub Actions はビルド前に SSH で取得し、ビルド後に更新分を書き戻す。リポジトリと GitHub の cache には置かない。
- 取り込み: `src/lib/catalog.ts` で content_id をキーに生成文を結合し、無い作品は今のテンプレート文にする。
- 生成の入力: 題名・出演者・メーカー・シリーズ・ジャンル・収録時間・配信日・評価だけ。公式の紹介文は渡さない（転載を防ぐ）。
- 検査: 禁止語（未成年を連想させる語、実在の第三者の固有名詞）、文字数、データに無い数値の混入を機械的に検査してから保存する。

## 6. 運営者に決めてもらうこと
1. 段階 1（非露骨の自動化）を先に進めてよいか。
2. 段階 3 の試験（100 作品、費用は数百円〜千円程度と GPU の時間）をやるか。やるなら、露骨さの度合いと「出演者名を性的描写に含めない」線引きを運営者が決める（文体の指示文は運営者が書く。AI 側の担当はそれを機械的に適用する仕組みまで）。
3. 段階 2 の道具として Muse を運営者が試すか（アプリで無料枠があるかは要確認）。
