# 15 原稿の書き方（運営者向け）

2026-11-23。DMM の承認に必要な「自作コンテンツ」を運営者が書くための手順。書くのは 7 つ。運営者は Google ドキュメントに書き、AI（Claude）が Markdown に整えて配置し、仮公開で表示を確かめてから公開する。

## 1. 流れ

1. Google ドキュメントを 1 本作る（名前は「AVめぐり 原稿」など）。3 章の型をそのまま貼り、書けたものから埋める。
2. 1 本でも書けたら、ドキュメントの共有リンク（「リンクを知っている全員」が閲覧可）を会話に貼る。
3. AI が Markdown に整え、作品 ID を確かめて配置し、仮公開（avmeguri.com）に配信する。表示を見て、直したい所を会話で言う。
4. OK になったものから公開する（`draft` を `false` にする）。ガイド 3 本・特集 2 本・運営者情報がそろったら、運営者が DMM アフィリエイトで媒体（avmeguri.com）を登録して申請する。

一度に全部でなくてよい。1 本ずつ送れば、その日のうちに反映する。

## 2. 書くもの 7 つ

| # | 置き場所 | 分量の目安 | 中身 |
|---|---|---|---|
| 1 | 運営者から（トップの上部） | 3〜6 行 | 今週見たもの、気づいたこと、サイトの使い方を 1 つ。人の声で |
| 2 | 運営者情報の所在地 | 都道府県 1 語 | 「東京都」など。運営者名は屋号「AVめぐり編集部」、連絡先は info@avmeguri.com で固定（決定事項 2026-11-15） |
| 3 | ガイド 1「このサイトの使い方」 | 800〜1,500 字 | 棚・ぶらぶら・探索・新着・セールの使い分け、ラベルの意味 |
| 4 | ガイド 2「はじめての 1 本の選び方」 | 800〜1,500 字 | 迷う人にどう選ばせるか。短い・評価が高い・定番、の考え方 |
| 5 | ガイド 3「出演者・シリーズ・メーカーの軸で探す」 | 800〜1,500 字 | 1 本気に入ったあとの広げ方 |
| 6 | 特集 1 | 導入 3〜6 行 ＋ 作品 5〜10 本（各 1〜2 文） | テーマは運営者が決める |
| 7 | 特集 2 | 同上 | 同上 |

ガイドの題は変えてよい（3 本のテーマは雛形 `src/content/guide/` の仮題）。

## 3. 型（ドキュメントにこの順で書く）

### ガイド

```
【ガイド 1】
題名: （30 字以内）
説明: （100〜120 字。検索結果と一覧のカードに出る。何が分かる記事かを 1〜2 文で）
本文:
（見出しを「## 」で始めて、800〜1,500 字）
```

### 特集

```
【特集 1】
題名: （30 字以内。例: 夜ふかしの 1 本に。90 分以内で評価の高い 8 本）
説明: （100〜120 字）
導入: （3〜6 行。なぜこのテーマか、どう選んだか）
作品:
1. ID または 題名＋出演者名 ── 一言（1〜2 文。何がよいか、どんな日に向くか）
2. …
締め: （任意。2〜3 行）
```

### 運営者から

```
【運営者から】
日付: 2026-11-XX
本文: （3〜6 行）
```

### 運営者情報

```
【運営者情報】
都道府県: 
```

## 4. 作品の指定のしかた

- いちばん確実なのは、サイトの作品ページの URL の末尾。`https://avmeguri.com/v/125umd01017/` なら `125umd01017`。
- FANZA の URL でもよい（`cid=` のあとの文字列）。
- 分からなければ「題名＋出演者名」で書く。AI が探して ID を確かめる。カタログに無い作品（掲載範囲の外）はその旨を伝える。
- 特集のテーマが決まったら 1 行で言えば、候補の一覧（ID、題名、出演者、評価、レビュー数、収録時間、配信日）を AI が出す。用意してあるテーマは 4 つ: 定番（レビュー 100 件超）、今月の高評価、短くて評価の高い入門向け、セール中の高評価。別のテーマでも作れる。

## 5. 書くときのルール（規約・法律・サイトの方針）

- 公式の商品紹介文とユーザーレビューは写さない。要約も当面しない（DMM に照会中）。自分の言葉で書く。
- 性的に露骨な描写は書かない。「作風」「見どころ」「どんな気分の日に合うか」までにする。理由は 2 つ。文はリポジトリ（GitHub）に入るので露骨な文を置けない決まりであること、X への投稿や検索結果にも使うこと。
- 価格、割引率、セールの期限は書かない（変わる。ページには自動で出る）。
- 出演者については、公式 API のデータにある事実（作品数、配信開始の時期など）以外の個人情報・推測・容姿への評価は書かない。
- 18 歳未満を連想させる語は使わない。ビルド時の禁止語の検査で止まる。
- 他サイトや他人の文章は貼らない。画像は不要（AI が公式の配信 URL で入れる）。「PR」の表記は自動で付く。
- 文体は一人称「私」か「編集部」。レンタル店の 18 禁コーナーの話のような、自分の体験と好みを書く。定型句（「〜をご紹介します」「いかがでしたか」）は避ける。
- 運営者の本名・ハンドル名・勤務先は書かない（身元の保護。決定事項 2026-11-15）。

## 6. 公開と申請までのチェック

- [ ] 運営者から 1 本（公開）
- [ ] 運営者情報の都道府県
- [ ] ガイド 3 本（公開）
- [ ] 特集 2 本（公開）
- [ ] 上がそろったら、運営者が DMM アフィリエイトで媒体を登録して申請する（通常 3 営業日）
- [ ] 承認後、AI が本公開に切り替える（検索に載せる、アフィリエイト ID を入れる。docs/07 3.3）

## 7. AI 側の作業（参考）

- ガイド: `src/content/guide/<英数の名前>.md`。frontmatter は `title`、`description`、`date`、`draft`。
- 特集: `src/content/feature/<英数の名前>.md`。上に加えて `works`（content_id の配列。数字だけの ID は `""` で囲む）と `intro`。本文の下に作品カードが `works` の順で並ぶ。カタログに無い ID はビルド時に警告。
- 運営者から: `src/content/notes/YYYY-MM-DD.md`。frontmatter は `date`、`source: operator`、`draft: false`。同じ週は週次の自動生成が止まる（docs/07 10 章）。
- 運営者情報: `src/pages/about.astro` の所在地。
- 配置したら `npm run build`（禁止語・リンクの検査を含む）→ Smoke の `[smoke days=1 ranked=5 deploy noprofiles]` か日次の配信で仮公開へ。
