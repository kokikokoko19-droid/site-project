## 2. 認証と最小構成
- OAuth 1.0a User Context（旧式扱いだが利用可）か OAuth 2.0 PKCE（tweet.read / tweet.write / users.read、長期運用は offline.access、画像は media.write。トークン2時間）。
- 最小構成: 開発者コンソールでApp作成、Read and write に設定、Access Token/Secret を再生成、クレジット購入、4つのキーを環境変数に、`POST /2/tweets`。従量課金未登録だと 403 の報告あり。

## 3. 成人向けポリシーとラベル
- 合意のもと制作・配布された成人向けコンテンツは、警告ラベル付きで、目立つ場所以外なら許可。ライブ動画、プロフィール画像、ヘッダー、リスト/コミュニティの画像では禁止。18歳未満と生年月日未設定の閲覧者には表示されない。未ラベルは X 側がラベルや設定変更を行う。
- ラベル付け: アカウント設定「投稿するメディアにセンシティブな内容が含まれる」で常時ラベル。API ではメディア単位に `POST /2/media/metadata` の `sensitive_media_warning`（adult_content / graphic_violence / other）で指定可。JSON の形式は版により不一致があり **実機検証が必要**。`POST /2/tweets` の `possibly_sensitive` 入力は見当たらない。
- Automation rules は、自動投稿でも成人向けならアカウントをセンシティブ設定にするよう求める。

## 4. リンクと自動化の制限
- X 幹部は「リンクの減点はしていない」と説明（2026年）。規則面では、コメントなしのリンク連投が活動の大半を占めること、リダイレクトや誤解を招くリンクが禁止。
- 同一・酷似投稿は1アカウントでも複数アカウントでもスパム。複数アカウントは目的が異なり非重複の場合のみ。
- 2026年5月から Premium 未加入は1日50投稿＋200返信（API 含む全クライアント合算）。

## 6. 運用設計への示唆
1. プランは従量課金のみ。1日3〜5本なら上限内。
2. 月額の目安: URL付き3本/日≒18ドル、URL付き10本/日≒60ドル、URLなし10本/日≒4.5ドル。
3. ラベルはアカウント設定の常時オンを基本に、画像添付時はメディア単位の指定を併用。テスト投稿で表示を確認。
4. 文面は毎回データ駆動で変え、同一リンク・同一文の連投を避ける。本文に「PR」を入れる。
5. 要実機検証: ラベルの JSON 形式、API 投稿へのアカウント設定の適用、メディア課金、403。画像の X への再アップロードが DMM 規約の直リンク原則と整合するかは別途確認。
